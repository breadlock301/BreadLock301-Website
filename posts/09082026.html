How Was The Website Overhauled Internally?

The previous website UI (and the first one before that) used a trick by PetraPixel, who I've mentioned so many times, it kinda weirds me out. Anyways, they designed a really cool website layout designer that included a fancy Javascript file that essentially wraps a layout around the contents of your page, so when you want to edit the layout, you just need to edit the Javascript file and the CSS file for formatting.

However, this design really sucked for my needs. For one, it requires a really messy template file that I need to use every single time I want to update a page, and if I needed to update the layout in a way that also requires updating a page? I STILL have to update EVERY. SINGLE pAGE. It doesn't help that I was using almost exclusively Neocities itself to manage the files, so I don't have access to any fancy tools to auto-generate every single page. I don't want to do that in general. I worry for how that would affect bandwidth and stuff.

Outside of that, I also like the old web... Of course, that also applies to old browsers. Yes, nobody's gonna use an old web browser anymore outside of nostalgic purposes, and I'm farily certain that you can't use most of them on most websites anymore, which probably includes Neocities. With that said, however, I still wanted to make a website that was compatable with older web browsers, because I felt that, if I did so, it would help me implicitly learn a lot about old website design in the process. Everytime I look at an image of an old site, I'm asking meselfs "how did they do that?" Right now, the answer is almost always "I have no fucking idea," but hey, maybe I'll eventually find a blog from someone who's actually documented all of the cool CSS tricks of the early 2000's.

Anyways, the new website is very different. While looking for an alternative to the previous system, I found out about url parameters. Y'know, where the links have a question mark after them, followed by stuff like "param=value", stuff like that.

Well, the context that I discovered these in (as an actual feature, and not smth for php pages) was in either a blog post or a stackoverflow answer (i forgot exactly) that used a Javascript file to read a url parameter in the index page named, well, "page," compared it's value to a list of "safe sites," and then loaded the contents of another html page into the main section of the index page. In other words, you have one primary page index.html (that's your main page btw) that you can design your layout in, and then you have other html pages with the home page, about me page, etc. that the Javascript inserts into index.html, depending on the url parameter named "page."

This is what I used as a basis for the new website design, where the layout and CSS was stored in index.html (I know, embedded CSS, ew.) The Javascript file is heavily modified from the original sample code, as I removed the safe page idea and made it a lot more flexible. For example, alongside the page parameter, there's also the id parameter, an idea taken from booru sites, which is used for indexing posts, like this one. Look at the url, it says "?page=posts&id=09082026"! This makes the entire posts system a lot cleaner overall, and means that it can be adapted to other parts of the website, too. The code currently also supports id indexing for a prohects and hobbies folder, so once I start working on those pages, any subpages will also have a clean index associated with it!

Oooh, oooh, another example! Some pages aren't actually their own html files, and are instead created directly in the Javascript! The previously mentioned navigation page, for example, isn't its own page, but is actually the contents of the navigation bar cut from index.html itself! Something like this wouldn't've been possible with the previous website code, so it's nice I can do stuff like this!

Of course, there's still some things I've needed to do. For example, you can't access index.html as a page, the website won't let you do that. You're also restricted on what characters can go into either parameter, to prevent potential sillies from being done. Also also, there's the obvious issue that. Well. You'd still be able to access those html files on their own. Of course, that's unacceptable, so I added some headers to those files that will redirect you to the intended url. Now, if you were to do this with the original template, you'll be stuck with a forever refreshing page, because the code uses document.write, which also causes any tags in the head section to be read, including the request to refresh the page. So to combat this, I had to add additional code that removes the head tags from the html page to be loaded. A bit hacky, but it's not too big of a deal, and I shouldn't have to touch it anyways, so mass editing of files still shouldn't be a problem.

Also also also (also? I lost track.), the javascript SHOULD be compatable with old browsers, too, so that's a bonus. I'm wondering if it would be possible to embed the Javascript into index.html in the same way the CSS is, thus bypassing any kind of cacheing, but. idk. For now, I'm fine with it being a separate file, I only need to incremement the version number in the tag that loads the Javascript, so it's not really a pain to edit it. Outside of a mistake I made with using relative pages instead of absolute pages, thus making posts inaccessible, I haven't had to do any modifications to pages or the javascript, and I don't think I'll need to anytime soon.
